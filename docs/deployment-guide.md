# คู่มือติดตั้งใช้งานจริงแบบ Local Windows

คู่มือนี้อธิบายวิธีใช้งาน BrakeCheck ในคอมบริษัทแบบ local-first สำหรับมือใหม่ โดยใช้เครื่องแม่ 1 เครื่อง และให้เครื่องอื่นเปิดผ่าน Chrome

## เอกสารนี้ใช้เมื่อไหร่

ใช้ไฟล์นี้เป็นคู่มือหลักเมื่อต้องติดตั้งหรือย้าย BrakeCheck ไปใช้งานจริงในบริษัท เช่น ตั้งเครื่องแม่, เครื่องลูก, IP, Firewall และ CORS

ถ้างานเป็นการย้ายไฟล์ด้วยแฟลชไดรฟ์ ให้เริ่มจาก `docs/usb-transfer-install-guide.md` แล้วกลับมาอ่านไฟล์นี้เฉพาะเรื่องเครื่องแม่/เครื่องลูกและ network
ถ้าต้องการรายละเอียดปุ่มกด Windows ให้ไปที่ `docs/windows-button-guide.md`
ถ้าต้องการ Backup/Restore แบบละเอียด ให้ไปที่ `docs/backup-restore-guide.md`
ถ้าต้องแก้ปัญหาเปิดเว็บไม่ได้, database health fail หรือ port `3000` ให้ไปที่ `docs/troubleshooting.md`

## ภาพรวมแบบสั้น

- เครื่องแม่: คอมหลักที่เปิด server และเก็บฐานข้อมูล MySQL
- เครื่องลูก: คอมเครื่องอื่นที่เปิดเว็บผ่าน Chrome
- ไม่ต้องติดตั้ง BrakeCheck ทุกเครื่อง
- ก่อนอัปเดตระบบหรือทำงานกับข้อมูลจริง ต้อง Backup database และไฟล์แนบก่อนเสมอ
- ก่อนใช้งานจริงในบริษัท ควรคุยกับ IT หรือหัวหน้างานก่อน
- ถ้าต้องส่งภาพรวมให้ IT ให้ใช้ไฟล์นี้คู่กับ `docs/backup-restore-guide.md` และอย่าส่ง `.env`, password, `backups/`, `*.sql` หรือข้อมูลโรงงานจริง

## เครื่องแม่คืออะไร

เครื่องแม่คือคอมหลักที่ติดตั้งและเปิดระบบ BrakeCheck

เครื่องแม่ทำหน้าที่:

- เปิด BrakeCheck server
- เก็บไฟล์โปรเจกต์ BrakeCheck
- เชื่อมต่อ MySQL database
- ให้เครื่องลูกเปิดเว็บเข้ามาใช้งานผ่านเครือข่ายภายในบริษัท

ถ้าเครื่องแม่ปิด เครื่องลูกจะเปิดเว็บ BrakeCheck ไม่ได้

## เครื่องลูกคืออะไร

เครื่องลูกคือคอมเครื่องอื่นในโรงงานหรือสำนักงานที่ต้องการใช้งาน BrakeCheck

เครื่องลูกต้องมี:

- Chrome
- อยู่ในเครือข่ายเดียวกับเครื่องแม่

เครื่องลูกไม่ต้องติดตั้ง Node.js, MySQL, Git หรือโค้ด BrakeCheck

## ทำไมไม่ควรติดตั้งทุกเครื่อง

ไม่ควรติดตั้ง BrakeCheck แยกทุกเครื่อง เพราะจะทำให้:

- ข้อมูลกระจายหลายฐานข้อมูล
- ไม่รู้ว่าเครื่องไหนคือข้อมูลล่าสุด
- Backup ยาก
- อัปเดตระบบยาก
- เสี่ยงข้อมูล QC ไม่ตรงกัน

แนวทางที่แนะนำคือให้มีเครื่องแม่ 1 เครื่อง แล้วให้เครื่องลูกเปิดผ่าน Chrome

## โปรแกรมที่ต้องติดตั้งบนเครื่องแม่

เครื่องแม่ควรมี:

- Chrome สำหรับเปิดเว็บทดสอบ
- Node.js สำหรับรัน backend server
- MySQL สำหรับเก็บข้อมูล
- VS Code สำหรับเปิดโปรเจกต์และแก้ไฟล์
- Git สำหรับอัปเดตโค้ดและดูสถานะงาน

ถ้าไม่แน่ใจว่ามีครบไหม ให้ดับเบิลคลิก:

```text
scripts/check-system.bat
```

## เครื่องลูกต้องมีอะไร

เครื่องลูกต้องมีแค่:

- Chrome
- การเชื่อมต่อเครือข่ายภายในบริษัทไปยังเครื่องแม่

ไม่ต้อง copy โปรเจกต์ไปเครื่องลูก

## วิธีเปิด server บนเครื่องแม่

ที่เครื่องแม่ ให้ดับเบิลคลิก:

```text
scripts/start-server.bat
```

ถ้า server เปิดสำเร็จ เครื่องแม่จะเข้าเว็บได้ที่:

```text
http://localhost:3000/
```

ห้ามปิดหน้าต่าง server ระหว่างมีคนใช้งานอยู่

ถ้าต้องการปิด server ให้กด `Ctrl+C` ในหน้าต่าง server แล้วตอบยืนยันถ้ามีถาม

## วิธีหา IP เครื่องแม่

ที่เครื่องแม่ เปิด PowerShell หรือ Command Prompt แล้วรัน:

```powershell
ipconfig
```

มองหาค่าที่ชื่อประมาณ:

```text
IPv4 Address . . . . . . . . . . . : 192.168.x.x
```

ตัวอย่าง IP:

```text
192.168.1.50
```

IP จริงของบริษัทอาจไม่เหมือนตัวอย่างนี้

## วิธีเปิดเว็บจากเครื่องอื่น

ที่เครื่องลูก เปิด Chrome แล้วเข้า URL ของเครื่องแม่:

```text
http://192.168.x.x:3000/
```

ตัวอย่าง:

```text
http://192.168.1.50:3000/
```

ถ้าเปิดจากเครื่องแม่เอง ให้ใช้:

```text
http://localhost:3000/
```

## วิธีตั้งค่า CORS สำหรับเครื่องแม่บริษัทและแท็บเล็ต Wi-Fi

CORS คือกติกาที่ server ใช้บอก browser ว่าเว็บจาก URL ไหนเรียก API ได้

เมื่อใช้งานจริงในบริษัท ให้ตั้งค่า CORS ให้รับเฉพาะ URL ที่ใช้จริงในบริษัท เช่น เครื่องแม่, เครื่องลูก และแท็บเล็ตที่เปิดผ่าน Wi-Fi บริษัท

### ขั้นที่ 1: หา IP เครื่องแม่

ที่เครื่องแม่ เปิด PowerShell หรือ Command Prompt แล้วรัน:

```powershell
ipconfig
```

ดูค่า `IPv4 Address` เช่น:

```text
192.168.10.50
```

ถ้าเป็นไปได้ ให้ IT ตั้ง IP เครื่องแม่ให้คงที่ หรือจอง DHCP ไว้ เพื่อไม่ให้ URL เปลี่ยนบ่อย

### ขั้นที่ 2: เปิดไฟล์ `.env`

เปิดไฟล์ `.env` ที่ root ของโปรเจกต์ BrakeCheck บนเครื่องแม่

หาแถวนี้ หรือเพิ่มใหม่ถ้ายังไม่มี:

```text
CORS_ORIGINS=
```

### ขั้นที่ 3: ใส่ URL ที่อนุญาต

ตัวอย่างสำหรับเครื่องแม่บริษัท IP `192.168.10.50`:

```text
CORS_ORIGINS=http://localhost:3000,http://127.0.0.1:3000,http://192.168.10.50:3000
```

ความหมายแบบง่าย:

- `http://localhost:3000` ใช้เปิดจากเครื่องแม่เอง
- `http://127.0.0.1:3000` ใช้เปิดจากเครื่องแม่เองอีกแบบหนึ่ง
- `http://192.168.10.50:3000` ใช้เปิดจากเครื่องลูกหรือแท็บเล็ตในบริษัท

ถ้า IP เครื่องแม่ไม่ใช่ `192.168.10.50` ให้เปลี่ยนเป็น IP จริงของบริษัท

ไม่ควรใช้ `*` เพราะจะเปิดกว้างเกินไป

### ขั้นที่ 4: Restart server

หลังแก้ `.env` แล้ว ให้ปิด server เดิมและเปิดใหม่ด้วย:

```text
scripts/start-server.bat
```

หรือถ้าใช้ Auto Start อยู่ ให้ restart เครื่องแม่ หรือหยุดแล้วเปิด server ใหม่ตามขั้นตอนของบริษัท

### ขั้นที่ 5: ทดสอบหลังตั้งค่า

ให้ทดสอบตามลำดับนี้:

1. เครื่องแม่เปิด `http://localhost:3000/`
2. เครื่องแม่เปิด `http://192.168.10.50:3000/`
3. เครื่องลูกเปิด `http://192.168.10.50:3000/`
4. แท็บเล็ตต่อ Wi-Fi บริษัท แล้วเปิด `http://192.168.10.50:3000/`
5. Login และลองเปิดหน้าหลัก เช่น Import, ตรวจ Lot, Approve, Report

ถ้าเครื่องแม่เปิดได้ แต่เครื่องลูกหรือแท็บเล็ตเปิดไม่ได้ ให้ตรวจ Firewall, วง Wi-Fi/LAN, และ IP เครื่องแม่ก่อน

## ข้อควรระวังเรื่อง Firewall

Firewall คือระบบป้องกันเครือข่ายของ Windows หรือบริษัท

ถ้าเครื่องลูกเปิดเว็บไม่ได้ แต่เครื่องแม่เปิด `http://localhost:3000/` ได้ อาจเป็นเพราะ Firewall บล็อก port `3000`

สิ่งที่ควรถาม IT:

- อนุญาตให้เครื่องลูกเข้าเครื่องแม่ที่ port `3000` ได้ไหม
- ต้องตั้งค่า Windows Firewall เพิ่มหรือไม่
- เครื่องแม่ใช้ IP คงที่ได้ไหม เพื่อไม่ให้ URL เปลี่ยนบ่อย

อย่าปิด Firewall เองถ้าไม่ได้รับอนุญาตจาก IT

## ข้อควรระวังเรื่อง MySQL

MySQL คือฐานข้อมูลที่เก็บข้อมูล QC

ข้อควรระวัง:

- เครื่องแม่ต้องเปิด MySQL อยู่
- ค่า `.env` ต้องชี้ไปฐานข้อมูลที่ถูกต้อง
- production ควรใช้ MySQL user เฉพาะระบบ เช่น `brakecheck_app` ห้ามใช้ `root`
- ห้ามใช้ฐานข้อมูลจริงเป็นที่ทดลอง
- ห้ามรันคำสั่ง `DROP`, `TRUNCATE`, หรือ reset database กับข้อมูลจริง
- ถ้าไม่แน่ใจว่าเป็นฐานข้อมูลจริงหรือทดสอบ ให้หยุดและถามก่อน

เครื่องลูกไม่ต้องต่อ MySQL โดยตรง ให้ใช้งานผ่านเว็บ BrakeCheck เท่านั้น

### MySQL user สำหรับ production

`root` คือ user ใหญ่สุดของ MySQL ถ้ารหัสหลุดหรือระบบพลาด อาจกระทบได้ทั้ง database

สำหรับใช้งานจริง ให้ IT สร้าง user เฉพาะ BrakeCheck และให้สิทธิ์เฉพาะฐานข้อมูล `brakecheck` เท่าที่ระบบต้องใช้:

```sql
CREATE USER 'brakecheck_app'@'localhost' IDENTIFIED BY '<strong-password>';
GRANT SELECT, INSERT, UPDATE, DELETE ON brakecheck.* TO 'brakecheck_app'@'localhost';
FLUSH PRIVILEGES;
```

จากนั้นตั้งค่า `.env` บนเครื่องแม่:

```text
DB_NAME=brakecheck
DB_USER=brakecheck_app
DB_PASSWORD=<strong-password>
```

ห้ามใส่รหัสผ่านจริงในเอกสารหรือ commit ขึ้น GitHub

ถ้าต้องสร้างตารางหรือรัน migration ให้ IT backup ก่อน แล้วใช้ account admin แยกชั่วคราว หลังจบงานให้ `.env` กลับมาใช้ `brakecheck_app`

## วิธีตั้ง SESSION_SECRET บนเครื่องบริษัท

`SESSION_SECRET` คือข้อความลับที่ระบบใช้เซ็น token สำหรับ login

เครื่องบริษัทแต่ละเครื่องควรมีค่า `SESSION_SECRET` ของตัวเองในไฟล์ `.env`

ขั้นตอน:

1. ที่เครื่องแม่ เปิด PowerShell
2. เข้าโฟลเดอร์โปรเจกต์ BrakeCheck
3. รันคำสั่งนี้เพื่อสร้างข้อความสุ่ม

```powershell
[guid]::NewGuid().ToString() + [guid]::NewGuid().ToString()
```

4. copy ผลลัพธ์ที่ PowerShell แสดง
5. เปิดไฟล์ `.env` ที่ root ของโปรเจกต์
6. หาแถวนี้:

```text
SESSION_SECRET=replace_with_random_text_at_least_32_chars
```

7. แทนค่าหลัง `=` ด้วยผลลัพธ์ที่ copy มา
8. save ไฟล์ `.env`
9. เปิด server ด้วย `scripts/start-server.bat`

ถ้า `SESSION_SECRET` ว่าง สั้นเกินไป หรือยังเป็นค่าตัวอย่าง server จะเปิดไม่ขึ้น ให้กลับมาตรวจไฟล์ `.env` อีกครั้ง

ห้ามส่งไฟล์ `.env`, ค่า `SESSION_SECRET`, database password หรือข้อมูลจริงขึ้น GitHub

## ต้อง Backup ก่อนอัปเดต

ก่อนอัปเดตระบบ, Import Excel จำนวนมาก, หรือเปลี่ยนโครงสร้างฐานข้อมูล ให้ Backup ทั้ง database และไฟล์แนบก่อน

วิธี Backup แบบปุ่มกด:

```text
scripts/backup-system.bat
```

ไฟล์ backup จะอยู่ในโฟลเดอร์:

```text
backups/
```

ควรตรวจว่าได้ทั้ง:

- ไฟล์ `.sql` สำหรับ database
- ไฟล์ `.zip` สำหรับ `storage/attachments`

ห้าม commit ไฟล์ backup ขึ้น GitHub

## ไม่ควรปิดเครื่องแม่ระหว่างใช้งาน

ถ้าปิดเครื่องแม่ระหว่างใช้งาน:

- เครื่องลูกจะเข้าเว็บไม่ได้
- ผู้ใช้ที่กำลังกรอกข้อมูลอาจบันทึกไม่สำเร็จ
- งาน QC อาจสะดุด

ก่อนปิดเครื่องแม่ ควรถามคนที่กำลังใช้งานก่อนเสมอ

## ก่อนใช้งานจริงควรถาม IT หรือหัวหน้างาน

ก่อนนำไปใช้งานจริงในบริษัท ควรถาม:

- เครื่องไหนจะเป็นเครื่องแม่
- ใครดูแลเครื่องแม่
- ต้องตั้ง IP เครื่องแม่ให้คงที่หรือไม่
- Firewall อนุญาต port `3000` หรือไม่
- MySQL ใช้ user เฉพาะระบบแล้วหรือยัง ห้ามใช้ `root` ใน production
- Backup database และไฟล์แนบเก็บไว้ที่ไหน และใครรับผิดชอบ
- ถ้าเครื่องแม่เสีย จะกู้ระบบจาก backup อย่างไร
- ช่วงเวลาไหนเหมาะสำหรับอัปเดตระบบ

## ขั้นตอนติดตั้งแบบย่อ

1. เลือกเครื่องแม่ 1 เครื่อง
2. ติดตั้ง Node.js, MySQL, Chrome, VS Code และ Git บนเครื่องแม่
3. ให้ IT สร้าง MySQL user เฉพาะระบบ เช่น `brakecheck_app`
4. ตั้งค่า `.env` บนเครื่องแม่ รวมถึง `DB_USER`, `DB_PASSWORD` และ `SESSION_SECRET`
5. ตรวจระบบด้วย `scripts/check-system.bat`
6. Backup ทั้งระบบด้วย `scripts/backup-system.bat`
7. เปิด server ด้วย `scripts/start-server.bat`
8. ทดสอบบนเครื่องแม่ที่ `http://localhost:3000/`
9. หา IP เครื่องแม่ด้วย `ipconfig`
10. เปิดจากเครื่องลูกด้วย `http://192.168.x.x:3000/`
11. ถ้าเครื่องลูกเข้าไม่ได้ ให้ถาม IT เรื่อง Firewall และเครือข่าย
